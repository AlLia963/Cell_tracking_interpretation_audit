# Generic typed-window input contract, v0.3.0

`account_typed_mask_window` accepts an ordered list/tuple of at least two processing views, two explicitly ordered `MaskFrame` reference frames, and a dictionary mapping directed reference-ID pairs to `continuation` or `division`. IDs may be zero or negative; frames come from explicit fields and are not inferred from IDs. Python integers and NumPy integer scalars within signed int64 are valid. Float/bool aliases and overflow are rejected before integer conversion. Frame indices must retain the exact float-integer bookkeeping range already imposed by the unchanged graph module.

Each processing view is exactly a dictionary of `previous`, `current`, `edges`, and `division`. Both frames must contain unique integer IDs, aligned boolean NxHxW supports, explicit integer frame indices and support declarations. IDs cannot be reused between its two frame slots. Reference and prediction frame indices/order and registered per-slot pixel grid must agree across the processing history. This validates declared registration and schema; it does not certify physical registration or biological support meaning.

Raw/division pair collections may be lists, tuples, sets, frozensets, or two-column NumPy arrays. Individual pairs may be two-element lists, tuples, or one-dimensional NumPy arrays. Every pair is validated before a set is constructed. Repeated pairs still present in a sequence are rejected; a caller-created set has already discarded any duplicate occurrence and cannot encode that historical duplication. Every raw pair points from an existing previous-frame ID to an existing current-frame ID, and every division pair belongs to the raw set. Reference pairs have the same endpoint/order requirement in their reference frames. These guards impose no daughter-count, biological-lineage or event-truth constraint.

`adjacent_difference_baseline` takes the same ordered processing views, exactly one domain dictionary per view, a directed queried reference edge and explicit relation kind. It shares validated raw/division pair normalization with the main API, so JSON list pairs are accepted consistently. Domain dictionaries require typed integer keys, identical supplied key sets across views, and both queried endpoint keys. Options are ordered ID sequences: unmatched references retain their existing empty tuple/list meaning, and explicit `None` candidates also mean absence. Non-None candidates must be current IDs; the queried source and target must belong to the previous and current slots respectively. Duplicate candidates, invalid scalar values, bool/float/overflow IDs, missing endpoints and unequal processing-view/domain lengths are rejected.

The baseline validates the completeness/identity of the supplied processing sequence and queried endpoint domains. It has no reference-frame input, cannot discover reference IDs omitted from every supplied dictionary, and does not rematch or certify the optimality of supplied correspondence domains. The main API constructs the complete reference-ID domain using the unchanged strict IoU >1/2 disjoint-reference envelope. Both interfaces report per-edge visibility under declared type views. The baseline remains a same-information observational comparator and is not an independent matcher, new scientific method, biological N, utility experiment, or causal explanation. Ambiguous visibility/pathways retain their existing withholding definition.

This API is available through `portable_analysis_candidate`. The repository's
constructed checks validate software contracts; they do not establish accuracy
on a biological cohort. The dataset-specific natural-CTC reader is not included
in this source release.
